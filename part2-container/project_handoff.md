# 냉장고 용기 인식 시스템 — 작업 인수인계 문서

## 1. 현재 프로그램의 목표

냉장고 상단에 설치된 카메라(XIAO ESP32-S3 Sense + OV3660)로 냉장고에 들어오고 나가는
용기를 자동으로 인식하고, 각 용기를 **고유한 개체로 구분**하여 데이터베이스에서 관리하는
스마트 냉장고 비전 시스템.

- 사용자가 용기를 넣으면 카메라가 감지 → 이미지에서 시각적 특징을 추출 → 기존 DB와 비교
- 처음 보는 용기면 새 고유 ID(예: `Container_001`)를 **자동 생성하여 등록**
- 이전에 등록된 용기면 기존 ID로 재식별하고, DB에서 "내용물", "마지막으로 넣은 날짜" 등 정보를 불러옴
- **핵심 목표**: 사용자가 매번 사진을 A용기/B용기로 수동 라벨링하거나 모델을 재학습시킬 필요가
  없어야 함 (재학습 없는 자동 등록/재식별)

### 사용자가 원하는 최종 결과물 — 2026-08-25 재확인

- 냉장고 문 또는 상단에 **고정 카메라 한 대**를 설치하고 실시간 스트리밍 영상을 계속 분석한다.
- 처음 보는 물건도 학습된 일반 종류에 따라 `텀블러`, `반찬 용기` 등으로 즉시 분류한다.
- 종류 분류와 별개로 개별 물건을 비교해, 기존에 기억한 용기면 기존 `Container_XXX`를 반환한다.
- 기존 DB 어느 용기와도 충분히 비슷하지 않으면 **처음 보는 개별 용기**로 판단한다.
- 최종 제품에서는 사용자가 등록 버튼을 누르고 10초 동안 돌리는 절차를 요구하지 않는다.
  냉장고에 넣는 자연스러운 짧은 동작 동안 얻은 여러 프레임으로 새 ID를 자동 생성하고,
  이후 반복 사용에서 확실한 새로운 각도를 점진적으로 추가해 기억을 보강한다.
- 고정 카메라의 촬영 위치와 입출고 동선이 반복되므로 우선 한 대로 구현·검증한다. 실제 냉장고
  시험에서 반대편 각도나 가림 문제가 해결되지 않을 때만 보조 카메라를 검토한다.
- 최종 처리 흐름:
  `실시간 영상 → YOLO 위치 탐지·크롭 → 종류 분류 → 기존 ID 재식별/신규 판단 → 자동 등록·DB 갱신`
- 사진만으로 완전히 동일한 브랜드·색상·크기의 복제 용기를 개체별로 구분하는 데에는 근본적인
  한계가 있으며, 필요한 경우 QR 또는 색상 마커를 보조 수단으로 사용한다.

### 설계 원칙 (중요)
객체 탐지(YOLO)와 개체 식별(임베딩)을 분리한다.
- **YOLO**: 화면에서 "용기가 어디 있는지" 위치만 찾음 (하나의 큰 클래스 `container`로만 학습 예정, 아직 미착수)
- **임베딩 모델**: YOLO가 찾은 영역을 크롭한 뒤, 별도 모델로 시각적 특징을 숫자 벡터로 변환
- **DB 비교**: 새 벡터를 기존 벡터들과 코사인 유사도로 비교해 동일 개체 여부 판단

  - 사전학습된 ResNet50(ImageNet 가중치, 분류층 제거, 2048차원 임베딩)으로 각 사진의 벡터 추출
  - 같은 용기 사진끼리 vs 다른 용기 사진끼리 평균 코사인 유사도 계산
  - **결과**: 같은 용기 평균 0.5654 / 다른 용기 평균 0.4241 / 차이 +0.1413
  - **해석 당시**: 구분 가능성은 있으나 차이가 크지 않아 오분류 가능성 의심.
    원인으로 (a) 사진 배경 오염, (b) ResNet50이 개체 수준 구분에 최적화된 모델이 아닐
    가능성 두 가지를 의심 → 아래 2차 테스트로 검증함.

- **임베딩 방식 비교 테스트 (DINOv2 + 배경 제거, 2차)**: 완료. **최종 방식 채택 완료.**
  - 대상 데이터: `retest_data/container_dataset {락앤락,생수병,원형용기}` 각 100장
  - `container_embedding_similarity_dinov2.py`: 원본 사진 그대로 DINOv2(ViT-S/14,
    torch hub `facebookresearch/dinov2`)로 임베딩 추출 후 ResNet50과 동일한 방식으로 비교
  - `container_embedding_similarity.py`: `rembg`(u2net 모델)로 사진마다 배경을 자동 제거해
    `cropped_dataset/`에 저장한 뒤, 원본/크롭 두 데이터셋에 각각 DINOv2를 적용해 결과를
    한 번에 비교하도록 개선. `rembg`/`onnxruntime` 패키지 설치 필요(설치 완료, u2net 모델은
    `C:\Users\PKNU-ICEE\.rembg\models`에 자동 캐시됨).
  - **결과 비교표**:

    | 조합 | 같은 용기 평균 | 다른 용기 평균 | 차이(구분력) |
    |---|---|---|---|
    | 원본 × ResNet50 | 0.5654 | 0.4241 | +0.1413 |
    | 원본 × DINOv2 | 0.5378 | 0.3332 | **+0.2047** |
    | 배경 제거(크롭) × DINOv2 | 0.4853 | 0.2864 | +0.1989 |

  - **결론**:
    1. DINOv2가 ResNet50보다 개체 구분력이 뚜렷하게 좋음 (+0.14 → +0.20).
    2. `rembg`로 배경을 제거해도 구분력은 좋아지지 않았음(오히려 살짝 하락). 냉장고처럼
       복잡한 배경에서 u2net이 용기 윤곽을 깔끔하게 못 잘라냈을 가능성이 있음. 즉 배경이
       오히려 노이즈가 아니라 일부 구분 단서로 작용했을 수 있음.
    3. **최종 채택: 원본 사진 × DINOv2(ViT-S/14)**. 이후 단계(DB 연동 등)는 전부 이 조합
       기준으로 진행한다. 배경 제거 경로는 이번 데이터에서는 기각했지만, 용기 종류가 늘거나
       실제 냉장고 환경(더 복잡한 배경)에서 정확도가 떨어지면 다시 검토할 수 있으므로
       `cropped_dataset/`과 스크립트는 삭제하지 않고 보존.
  - **산출물**: `similarity_result.csv/png`(원본×ResNet50), `similarity_result_dinov2.csv/png`
    (원본×DINOv2), `similarity_result_compare.csv/png`(원본×DINOv2 vs 크롭×DINOv2 비교),
    `cropped_dataset/`(배경 제거된 사진, 참고 보존용)

## 4. 코딩할 때 주의할 점

- **개발 순서를 건너뛰지 말 것**: 반드시 (1) 정적 이미지로 임베딩/재식별 검증 → (2) DB 연동 →
  (3) YOLO 탐지 학습 → (4) ESP32 실시간 연결 순서로 진행. 처음부터 실시간 카메라나 대량
  라벨링에 손대지 않는다.
- **이 프로젝트의 근본적 한계**: 완전히 동일하게 생긴 용기(예: 같은 브랜드/사이즈 락앤락
  여러 개)는 사진만으로 개체 구분이 원칙적으로 어렵다. 만약 실제 사용할 용기들이 서로
  구분이 안 될 만큼 비슷하게 생겼다면, 이 임베딩 기반 접근 자체가 통하지 않을 수 있으므로
  QR코드/컬러 스티커 등 마커 기반 방식으로 전환하는 것도 대안으로 열어둘 것. 하지만 가능한
서로 구분 되는 용기들로 프로젝트 진행할 예정.모양이 같더라도 색이 다르거나 색이 같더라도 모양
이 다르거나 같은 식으로 다를것.
- **프로젝트 방향이 한 번 크게 바뀐 이력이 있음**: 초기에는 용기 A~I를 YOLO로 직접 이름별
  분류하는 방식(재학습 필요)으로 설계했다가, "재학습 없이 새 용기 자동 등록"이 목표로
  확정되면서 지금의 임베딩 기반 재식별 방식으로 전환함. 방향이 다시 바뀔 수 있으므로,
  원본 사진(라벨링 안 된 상태)은 계속 보존해 두는 것을 원칙으로 함.
- **임베딩 방식은 이미 결론이 남 (원본×DINOv2)**: 배경 제거(rembg) 경로는 테스트해봤지만
  구분력이 더 안 좋아서 기각했음. 같은 실험을 다시 반복할 필요 없음. 단, 용기 종류가 늘거나
  실제 냉장고 환경에서 원본×DINOv2 정확도가 부족하면 그때 `cropped_dataset/` 및
  `container_embedding_similarity.py`의 배경 제거 로직을 다시 참고해서 재검토.
- **sqlite3는 파이썬 내장 모듈**이라 별도 설치 불필요. `rembg`, `onnxruntime`은 배경 제거
  실험을 위해 추가 설치함(`pip install "rembg[cpu]"`) — DB 연동 단계에서는 불필요.
- **사용자는 비전공자**임. 코드 설명은 쉽게, 터미널에 바로 붙여넣을 수 있는 구체적인 명령어
  형태로 제공할 것.
- 개발 환경은 Orca(ADE) + Claude Code 조합. git은 설치되어 있음.
